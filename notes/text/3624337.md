# 3624337 – Handling Replication Flow during SAP S/4HANA system upgrade

Version 6 · freigegeben 30.07.2026 · Komponente DS-DI-DF · [in SAP for Me öffnen](https://me.sap.com/notes/3624337)

SAP Knowledge Base Article

3624337 - Handling Replication Flow during SAP S/4HANA system upgrade
Component: DS-DI-DF (SAP Datasphere > Data Integration/Data Builder > Data Flow Runtime), Version: 6,
Released On: 30.07.2026

## Symptom

During an SAP S/4HANA system upgrade, replication flow fails to complete the cleanup phase after the initial load.
A similar message can be seen:
"Action is not possible; An upgrade is currently in process."
Also, an error message is displayed in the Data Integration Monitor:

The error message indicates that the system is in an upgrade state, and replication activities are temporarily paused to avoid data inconsistencies.

"Image/data in this KBA is from SAP internal systems, sample data, or demo systems. Any resemblance to real data is purely coincidental."

## Environment

SAP Datasphere as the subscriber
SAP S/4HANA as the provider

## Cause

It is not possible to perform cleanup of source replication artifacts during a system upgrade. This is by design to prevent data inconsistencies.

## Resolution

As the error messages suggests, the failure occurs because an upgrade is in progress in the source SAP S/4HANA system, which has triggered system locks. These
locks prevent the replication flow from completing the cleanup phase after the initial load.
To avoid any kind of data inconsistencies, it is intended that Replication flow is to be paused during system upgrade phase and is to be again resumed after system
upgrade is finished.
Therefore, it is not possible to perform cleanup of source replication artifacts during a system upgrade. Only after upgrade has finished would you be able to resume
this action.

## See Also

Refer to the Help Portal:
You must always stop or pause a running replication flow before a source system downtime
When you resume the flow, the system replicates all source data changes that happened while the replication flow was paused, which means that the
first replication flow run after a pause can take considerably longer than usual.
