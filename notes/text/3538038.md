# 3538038 – Important considerations for SAP Datasphere object store

Version 10 · freigegeben 09.10.2026 · Komponente DS · [in SAP for Me öffnen](https://me.sap.com/notes/3538038)

SAP Note

3538038 - Important considerations for SAP Datasphere object store
Component: DS (SAP Datasphere), Version: 10, Released On: 09.10.2026

## Symptom

This SAP Note describes important considerations when using the new object store in SAP Datasphere. It explains known
feature constraints and provides a workaround if one is available.
The list of important considerations is categorized in different functional areas to provide a better overview.
General
To use object store in SAP Datasphere, you must first configure the Object Store values in the Tenant Configuration
screen
Spaces must no longer be re-deployed after 30 days.
We recommend that you update the HANA Database to the latest patch version to improve system stability. This update
of the HANA DB can be triggered using this self-service.
To use the object store in SAP Datasphere, you need to create a new space and choose “SAP HANA Data Lake Files
storage“. There is currently no ability to enable it for existing spaces.
For each SAP Datasphere tenant, you can currently create up to a maximum of 20 spaces leveraging the object
store option, more can be request by a ticket to the component DS-SM.
The deployment time for creating a file space can take some time (up to 45 min) depending on your system, and no
artefacts can be deployed in that space until the space is deployed successfully.
Note: The creation of a file space is also creating the underlying Apache Spark instance, which requires some time to be
deployed successfully.
The current maximum size of VCPU for Apache Spark that can be assigned is 2048.
The usage of the object store is not supported for SAP Datasphere tenants using the one-tenant mode.
Replication Flow
The load type "initial + delta" must be used to replicate data into local tables (file) with replication flows. Data sources
that support only the load type "initial only" can currently not be used.
Example: Using object stores as source in Replication Flows is not supported.
The following data types are not supported when using local table (files) and is available here.
For example, columns having type “time” are not supported and skipped during the replication.
Datasets having column of type “time” as primary key are not supported, which is related to the bullet point above as
well as the need for having a primary key in general.
The following data types are automatically mapped to fulfil the pre-requisites when using local table (file) as target:
decfloat16 / decfloat34 are mapped to decimal(38,6)
unit64 is mapped to decimal (20,0)
Mapping a decfloat16 or decfloat34 to a fixed-point decimal in the Replication Flow mapping interface is not supported
when using local table (file) as target.
Usage of cluster tables as source from SAP ABAP systems is not supported when using local table (files) as target.
A so called “merge task” needs to be executed / scheduled by a user in a Task Chain to load the data into the local table
(file).
Note: There exists one merge task per data set / local table (file) that needs to run in a regular / scheduled fashion to

load the data into the local table (file). You can combine multiple merge tasks into a single task chain and execute it in a
certain frequency.
The Replication Flow monitoring in the “Data Integration Monitor” does currently not cover the status of the merge
task, which needs to be monitored separately using the task chain monitoring.
Transformation Flow
Please check the following link for using Transformation Flow in a File Space and also consider the important
considerations below.
The list of supported functions by a Transformation Flow in a file space is available here.
Usage of Currency Conversion is not supported.
Usage of “Truncate” option in the target table is not supported.
Data Preview for operators like, join, union, filter, view transform etc. is not supported.
When using Python, please take a look on the following documentation (link).

Local Table (Files)
You can find a list of restrictions in the SAP Datasphere help documentation (link).
The list of supported data types in a local table (file) is available here.
Altering an existing column after deployment of a local table (file) is not supported (e.g. changing data type, entering
default values etc.)
Removing an existing column after deployment of a local table (files) is not supported
Re-partitioning a local table (files) is not supported when data is already available in the table
Updating the primary key information of a local table (files) is not supported when data is already available in the table
Truncation of data (i.e. deleting all records) in a local table (files) is not supported
In case you want to submit a feature request, please use our Customer Portal for SAP Datasphere and check out our roadmap
explorer for upcoming innovations for SAP Datasphere.

## Reason and Prerequisites

You are using the object store in SAP Datasphere.
